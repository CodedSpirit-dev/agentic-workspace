# Project lifecycle

1. **Intake:** establish charter, objective, scope, authority, and success
   criteria. State is `planned`.
2. **Plan:** select mode and profile, register requirements, dependencies,
   initial risks, and the first cycle.
3. **Execute:** start phases, sprints, or workstreams; update typed tasks and
   evidence. State is `active`, `blocked`, or `at-risk`.
4. **Decide:** record material alternatives and consequences with stable
   decision IDs.
5. **Verify:** run reproducible checks and record actual results in `VER-*`
   artifacts.
6. **Deliver:** trace formal `DEL-*` artifacts to requirements and passed
   verifications, then record handoff and acceptance.
7. **Audit:** independently validate indexes, evidence, risks, cycles, and
   closure gates.
8. **Complete or archive:** close all active cycles, dispose material risks,
   record final status, and preserve history in place.

Completion requires every cycle to be terminal (`completed` or `cancelled`),
every risk to be explicitly disposed, every deliverable to be accepted or
otherwise terminal, and strict validation to pass. A `verified` deliverable is
still pending acceptance.

Traditional projects express this lifecycle through ordered phases. Sprint
projects repeat planning, execution, review, and retrospective in timeboxes.
Flexible projects run bounded workstreams and checkpoints. The evidence and
closure rules remain the same.
