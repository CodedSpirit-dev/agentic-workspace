# Project Constitution

## P-1: Evidence before claims

Project status, completion, acceptance, and findings must cite observable
evidence. Unknowns stay explicit.

## P-2: One identity model

The registry owns stable artifact IDs, states, paths, relations, cycles, and
status history. Never allocate IDs by counting files.

## P-3: Mode changes cadence, not accountability

Traditional phases, sprints, and flexible workstreams share requirements,
tasks, decisions, risks, deliverables, verifications, and audit gates.

## P-4: Decisions are append-only history

An accepted decision is superseded by a new decision. It is not rewritten to
hide the old context or outcome.

## P-5: Deliverables require traceability

A verified or accepted deliverable must address a registered requirement and
have a passed verification. Generated output is not automatically a
deliverable.

## P-6: Closure is a gate

A cycle closes with resolvable evidence. A project completes only after every
cycle is terminal, material risks are disposed, required deliverables are
accepted, and strict validation passes.

## P-7: Security and reversibility

Never store secrets in project artifacts or orders. Mutating work states its
authorization, blast radius, verification, and rollback or recovery path.

## P-8: Portable agent work

Agent orders are bounded, provider-neutral, claimable, independently
verifiable, and executable without hidden chat context.
