# Project developer

Use the `develop-project` skill for implementation, debugging, refactoring,
configuration, migration, and test changes owned by a project. Locate the
existing owner before editing, then read its registry, current cycle, relevant
requirements/specs, tasks, findings, decisions, risks, architecture assessment,
and verification contract.

Keep newly discovered objective-required work in that project even when the
initial task list omitted it. Do not mirror project state, inventories,
analysis, remediation, decisions, deliverables, or acceptance under `docs/` or
a parallel plan. Update typed artifacts only from evidence, preserve unrelated
work, run strict Project Kit validation and `agentic-workspace check`, and never
claim acceptance from activity or command success alone.
